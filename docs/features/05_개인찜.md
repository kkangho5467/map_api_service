# 05. 개인 찜

> 완성일: 2026-09-28 · 관련 파일: `supabase/06_likes.sql`, `src/hooks/useLikes.js`, `src/components/DetailSheet.jsx`, `src/App.jsx`

## 왜 만들었나
커플이 "둘 다 가고 싶은 곳(교집합)"을 찾으려면, 먼저 각자 가고 싶은 곳을 저장할 수 있어야 합니다.
커플 공유 전에 **나 혼자 쓰는 찜**부터 만들었습니다.

## 어떻게 동작하나
```
상세 모달 ♡ 클릭 → 화면 먼저 ♥로 변경 → likes 테이블에 insert
                                    └ 실패하면 ♡로 되돌리고 안내 문구
상단 '♥ 찜한 곳' (또는 하단 찜 탭) → 내 찜 id에 있는 장소만 지도·목록에 표시
```
1. 로그인하면 `useLikes`가 내 찜 목록(장소 id 모음)을 불러옵니다.
2. ♡를 누르면 화면을 먼저 바꾸고(낙관적 업데이트) DB에 저장합니다.
3. DB는 `(user_id, place_id)` 조합을 기본키로 써서 같은 곳을 두 번 찜할 수 없습니다.
4. RLS가 "내 찜만 보고·추가·삭제"하도록 막아, 다른 사람 찜은 보이지 않습니다.
5. 로그인하지 않은 상태로 ♡나 찜 필터를 누르면 로그인 시트가 열립니다.

## 핵심 개념
| 용어 | 쉬운 뜻 |
|---|---|
| 복합 기본키 | 두 칸을 합쳐서 "한 줄의 이름표"로 씀 → 같은 (사람, 장소) 중복 불가 |
| `default auth.uid()` | 앱이 user_id를 안 보내도 DB가 "지금 로그인한 사람"으로 채움 |
| 낙관적 업데이트 | 서버 응답을 기다리지 않고 화면부터 바꾸고, 실패하면 되돌리는 방식 |
| Set | 중복 없는 모음. `has()`로 "찜했나?"를 빠르게 확인 |

## 이렇게 설명하세요
> 장소 상세에서 하트를 누르면 내 찜 목록에 저장되고, '찜한 곳' 필터로 모아 볼 수 있습니다.
> 찜은 (사용자, 장소) 두 칸을 합친 기본키로 중복을 막고, RLS(행 단위 보안 규칙)로 본인 찜만 다룰 수 있게 했습니다.
> 누르자마자 반응하도록 화면을 먼저 바꾸고, 저장에 실패하면 원래대로 되돌립니다.
