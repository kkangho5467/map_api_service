# 02. 마이페이지 · 커플 연결

> 완성일: 2026-09-26 · 관련 파일: `supabase/02_profiles_couples.sql`, `src/hooks/useProfile.js`,
> `src/components/AccountSheet.jsx`, `CoupleCard.jsx`, `ProfileEditor.jsx`, `src/lib/image.js`

## 왜 만들었나
Pop-Pin은 **커플 앱**이라 "두 사람이 한 팀"이라는 연결이 있어야 교집합 찜·코스 추천·아카이브를 할 수 있습니다.

## 어떻게 동작하나
```
첫 로그인 ──(트리거)──▶ profiles 자동 생성 (닉네임·사진·6자리 초대 코드)
내 코드를 연인에게 전달 → 연인이 입력 → connect_couple() 함수 → couples 1행 + couple_members 2행
                                                          → 두 사람 화면에 D+N 표시
```
- **프로필**: 카카오 닉네임·사진으로 시작하고, 이후 직접 수정합니다. 사진은 512px로 줄여서 올립니다.
- **초대 코드**: 헷갈리는 글자(0/O, 1/I/L)를 뺀 6자리입니다.
- **한 사람 = 한 커플**: `couple_members`의 기본키가 `user_id`라서 DB가 중복 연결을 막아 줍니다.

## 핵심 개념
| 용어 | 쉬운 뜻 |
|---|---|
| 트리거 | "새 행이 생기면 자동으로 이것도 해라" — 가입 시 프로필 자동 생성 |
| RPC 함수 | 화면이 DB에 "이 함수 실행해 줘"라고 부르는 것. 검사 로직을 DB 안에 둬서 조작을 막음 |
| RLS | 행 단위 보안. **내 정보 + 내 연인 정보만** 보이게 DB가 직접 검사 |
| security definer | 함수가 관리자 권한으로 실행됨 → 일반 사용자는 못 하는 insert를 함수만 할 수 있게 |
| Storage 버킷 | 파일 저장소. `avatars/내-id/` 폴더에만 올리고 지울 수 있음 |

## 사용한 도구
| 도구 | 종류 | 왜 썼나 |
|---|---|---|
| Supabase DB · Storage | 외부 서비스 | 프로필·커플 데이터와 사진 저장 |
| Supabase SQL Editor | 외부 서비스 | 테이블·함수·보안 정책을 SQL 파일로 한 번에 적용 |

## 보안 설계 포인트
- 테이블에 직접 쓰기(insert/update/delete)를 막고, **검사가 들어 있는 함수로만** 커플을 연결·해제합니다.
- 프로필에서 수정 가능한 칸은 **닉네임·사진뿐**입니다(초대 코드 위조 방지).
- `my_couple_id()` 도우미 함수 → 보안 정책 안에서 같은 테이블을 다시 조회할 때 생기는 무한 반복을 예방합니다.

## 이렇게 설명하세요
> "가입하면 트리거가 프로필과 초대 코드를 자동으로 만들고, 연인이 코드를 입력하면 DB 함수가 검사한 뒤 커플을 연결합니다. 테이블에 직접 쓰는 권한은 막고 검사가 들어 있는 함수만 열어 두었으며, RLS로 나와 연인의 정보만 조회되게 했습니다. 한 사람이 두 커플에 속하지 않도록 DB 기본키로 규칙을 강제했습니다."
