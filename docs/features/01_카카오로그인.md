# 01. 카카오 로그인

> 완성일: 2026-09-26 · 관련 파일: `src/hooks/useAuth.js`, `src/components/AccountSheet.jsx`

## 왜 만들었나
찜·커플 연결·아카이브는 모두 **"누구의 데이터인지"** 알아야 합니다. 한국 사용자에게 가장 익숙한 카카오 계정으로 가입 절차 없이 바로 로그인하게 했습니다.

## 어떻게 동작하나
```
① 로그인 버튼 → ② 카카오 동의 화면 → ③ 카카오가 Supabase에 결과 전달
      → ④ Supabase가 세션(로그인 증표) 발급 → ⑤ 우리 사이트로 돌아옴 → 화면이 로그인 상태로 바뀜
```
- 비밀번호를 우리가 직접 저장하지 않습니다. 카카오와 Supabase가 인증을 대신 처리합니다.
- `getSession()`으로 저장된 세션을 확인하므로 **새로고침해도 로그인이 유지**됩니다.
- `onAuthStateChange`로 로그인·로그아웃이 일어날 때마다 화면을 자동으로 갱신합니다.

## 핵심 개념
| 용어 | 쉬운 뜻 |
|---|---|
| OAuth | "카카오가 이 사람 맞다고 보증해 줄게" — 다른 서비스에 로그인을 맡기는 표준 방식 |
| 세션 | 로그인했다는 증표. 브라우저에 저장돼 있어 매번 다시 로그인하지 않아도 됨 |
| Redirect URL | 로그인이 끝나고 **돌아올 주소**. 미리 등록한 주소로만 돌아올 수 있음(보안) |
| Client Secret | 카카오와 Supabase만 아는 비밀 값. Supabase 대시보드에만 저장, 코드에 넣지 않음 |

## 사용한 도구
| 도구 | 종류 | 왜 썼나 |
|---|---|---|
| Supabase Auth (Kakao Provider) | 외부 서비스 | 로그인·세션 관리를 직접 만들지 않고 맡기기 위해 |
| 카카오 디벨로퍼스 | 외부 서비스 | 카카오 로그인 활성화, Redirect URI 등록 |

## 막혔던 점 → 해결
- **KOE205** → Supabase가 항상 이메일을 요청하는데 카카오 앱에 이메일 동의 항목이 없음 → 비즈 앱 전환 후 이메일(선택) 동의 설정
- **KOE006** → 카카오에 Redirect URI 미등록 → REST API 키 설정에서 Supabase 콜백 주소 등록
- **로그인 후 배포 주소로 튕김** → 개발 서버가 5174 포트로 떠서 등록된 5173 주소와 불일치 → 기존 서버 종료 후 5173으로 재실행

## 이렇게 설명하세요
> "카카오 로그인은 OAuth 방식으로, 인증은 카카오와 Supabase Auth에 맡기고 저희는 비밀번호를 저장하지 않습니다. 로그인 후 받은 세션을 브라우저에 보관해 새로고침해도 로그인이 유지되고, 로그인 상태가 바뀌면 구독 기능으로 화면이 자동 갱신됩니다. 비밀 값은 서버(Supabase)에만 두고 프론트 코드에는 공개 키만 사용했습니다."
