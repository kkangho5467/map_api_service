# 06. 안드로이드 앱 (APK · TWA)

> 완성일: 2026-09-28 · 관련 파일: `public/manifest.webmanifest`, `public/sw.js`, `public/.well-known/assetlinks.json`, `src/main.jsx`, `index.html`

## 왜 만들었나
브라우저 주소를 입력하지 않고, 휴대폰 홈 화면의 아이콘으로 바로 여는 "진짜 앱"처럼 쓰고 싶었습니다.

## 어떻게 동작하나
```
[APK 앱 실행] → 크롬 엔진으로 map-api-service.vercel.app 을 전체 화면으로 엶
        └ 사이트의 /.well-known/assetlinks.json 확인 → 서명 일치하면 주소창 숨김
```
1. `manifest.webmanifest`에 앱 이름·아이콘·색을 적고, 서비스 워커를 등록해 "설치 가능한 웹앱(PWA)"으로 만들었습니다.
2. PWABuilder 사이트가 이 정보를 읽어 APK와 서명 키를 만들어 줍니다.
3. `assetlinks.json`으로 "이 사이트와 이 앱은 같은 주인"임을 증명해 주소창을 숨깁니다.
4. 앱은 웹사이트를 열 뿐이라, Vercel에 배포하면 앱도 자동으로 최신이 됩니다.

## 핵심 개념
| 용어 | 쉬운 뜻 |
|---|---|
| PWA | 설치할 수 있는 웹사이트 (manifest + 서비스 워커) |
| TWA | 웹사이트를 크롬으로 전체 화면으로 여는 안드로이드 앱 껍데기 |
| 서비스 워커 | 백그라운드에서 도는 작은 스크립트. 여기선 캐시 없이 "설치 조건"만 채움 |
| Package ID | 앱의 고유 주민번호 (`com.kkangho.datemap`). 스토어 출시 후 변경 불가 |
| 서명 키 | "이 앱을 만든 사람"을 증명하는 열쇠. 잃으면 업데이트 불가 |

## 사용한 도구 (스킬 · MCP)
| 도구 | 종류 | 왜 썼나 |
|---|---|---|
| feature-kickoff | 프로젝트 스킬 | TWA 방식·임시 아이콘 결정 후 단계별 계획 |
| security-checklist | 프로젝트 스킬 | 서명 키·APK가 GitHub에 올라가지 않게 `.gitignore` 추가 및 푸시 전 확인 |
| progress-log | 프로젝트 스킬 | 진행 기록과 이 노트 작성 |
| PWABuilder | 외부 웹 서비스 | Android Studio 없이 APK 생성 |

## 막혔던 점 → 해결
- "앱 설치" 메뉴가 안 보임 → 크롬 오른쪽 위 ⋮ 메뉴 안에 있었음
- 카톡·지메일로 APK 전송 안 됨 → 보안상 `.apk` 차단 → 구글 드라이브/USB로 전송
- Package ID를 나중에 못 바꾼다는 걱정 → 서비스 이름과 무관한 ID로 정함 (앱 이름·아이콘은 언제든 변경 가능)

## 이렇게 설명하세요
> 웹사이트를 PWA(설치 가능한 웹앱)로 만든 뒤, TWA 방식으로 감싸 안드로이드 APK로 배포했습니다.
> 앱은 배포된 사이트를 크롬 엔진으로 열기 때문에, 웹을 고치면 앱을 다시 설치하지 않아도 바로 반영됩니다.
> 사이트에 assetlinks.json을 올려 앱과 사이트의 소유자가 같음을 증명하고 주소창을 숨겼습니다.
