# Pop-Pin 동작 확인 절차

## 1. 빌드 확인 (항상)
프로젝트 `dist/`를 건드리지 않도록 스크래치 폴더로 빌드한다:
```
npx vite build --outDir <스크래치 디렉터리>/dist --emptyOutDir
```
실패하면 에러를 고치기 전까지 "완료"라고 보고하지 않는다.

## 2. 개발 서버 포트 확인
- `netstat -ano | grep -E ":517[0-9] .*LISTENING"`
- **반드시 5173**이어야 한다. 5174 이상이면 Supabase Redirect URL 불일치로 로그인 후 배포 주소로 튕긴다
  → 기존 서버를 모두 끄고 `npm run dev`를 다시 실행하도록 안내한다.
- 서버가 없으면 백그라운드로 `npm run dev`를 실행한다.

## 3. 화면 확인 (Playwright MCP가 연결돼 있을 때)
- 뷰포트 **390×844**(모바일)로 `http://localhost:5173` 접속
- 스크린샷을 찍어 변경한 부분이 의도대로 보이는지 직접 확인
- 콘솔 메시지에서 error가 없는지 확인 (카카오 SDK, Supabase 조회 에러 포함)
- 변경한 인터랙션을 실제로 클릭해 본다 (필터 칩, 마커, 바텀 시트, MY 탭 등)
- **로그인이 필요한 화면은 자동화하지 않는다** (카카오 계정 입력 금지). 사용자에게 직접 확인을 요청한다.

## 4. 흔한 문제
- 파일은 바뀌었는데 화면이 그대로 → HMR 누락. Ctrl+Shift+R, 안 되면 dev 서버 재시작
- 지도 회색 → `map.relayout()` / 컨테이너 크기 확인
- 배포 사이트만 옛날 화면 → 커밋·푸시 여부 확인 (사용자가 직접 푸시함)

## 보고 형식
- 확인한 것 / 확인 못 한 것(예: 로그인 화면)을 구분해서 짧게 보고한다. 확인하지 않은 것을 확인했다고 말하지 않는다.
